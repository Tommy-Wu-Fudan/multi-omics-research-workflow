# Independent skill acceptance protocol

Use a fresh executor with the selected skill, a realistic request, and minimum synthetic inputs. Do not supply expected answers, suspected defects, private project history, or an evaluator's conclusions. Write results to a new directory and compare the final files with unchanged inputs.

## Result trace

Use examples/result-trace/input. Check that the executor honors the approved source manifest over a misleading newer filename; separates OR/HR, raw P/FDR and model identities; accepts correct rounding and bounds; distinguishes no instruments from a null causal effect; checks effect scales and set directions; and avoids inventing support for treatment or mechanism claims.

Keep supported controls in the report. Split compound claims when a correct number and an unsupported interpretation occur together. Require source locations and input integrity evidence.

## Display revision

Provide a synthetic source table, existing figure and content contract. Request larger type and a new row order. Include a regular-marker adjusted-P rule and an explicitly different rule for one model.

Require editable source and a rendered preview. Inspect the actual plotted coordinates and intervals, row/model associations, stars, axis transformation, null line and retained text. Check final visual output and separately report target-application limitations.

## Scope controls

Provide a grammar-only request, a new-analysis request without core inputs, and a historical preprocessing allegation alongside corrected current code. Check that ordinary editing stays simple, missing analysis definitions are not invented, and current implementation is separated from historical execution.

On a material skill change, repeat the affected cases and at least one supported control. Record failures, corrections, exact skill hashes, environment and test limits; do not label unavailable checks as passing.
