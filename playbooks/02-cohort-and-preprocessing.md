# PB02: cohort, preprocessing, and reusable data checks

输入：只读原数据、字段说明、批准的研究合同。输出：派生数据、变量字典、逐步样本流、QC 和运行清单。所有规则都需来自本研究，不照搬其他项目的人群限制或阈值。

## 工作顺序

1. 核对 participant/sample/event 的分析单位与 ID 映射。按键合并前检查类型、唯一性、重复原因和 join cardinality；合并后核对新增/丢失样本和字段来源。不要打印或将受试者 ID 写进可分享的 Playbook。
2. 建立时间轴：基线、采样、诊断、死亡、失访、行政截止。说明排除发生在完整队列、病例表还是特定结局的 risk set。负时间、同日事件、冲突日期及缺失状态要显式处理。
3. 将编码规则同时写入代码和字典：原字段、instance/array、单位、特殊缺失码、阈值操作符、参考组、计算公式、适用人群和源版本。`>10%` 与 `>=10%` 不得靠标签猜测。
4. 原数据→清洗→派生分目录保存。旧项目目录不规范时用映射表接续，不为整理而迁移原数据。每次变换输出新文件或新 run 目录。
5. 缺失处理需按变量角色与分析目标决定。单次 median/mode 的不确定性未计入模型方差，不能称多重插补。MI 应检查收敛、合理性及与分析模型的相容性，逐插补拟合后合并估计及方差。官方 [mice pooling 文档](https://amices.org/mice/reference/pool.html)明确将插补、拟合和合并作为不同步骤。
6. 组学矩阵使用明确的 feature allowlist，不靠固定列号。排除 ID、结局和非特征字段后才计算缺失/近邻距离；记录矩阵行列含义、归一化/变换、KNN 方向与参数。预测任务的预处理只能在训练数据拟合，再应用于验证集。
7. 汇总 QC 至少包括各步 N、重复/未匹配数量、样本集合变化、每特征缺失率、变换后范围和单位、结局事件数、随访有效性、协变量完整性。只声明实际检查过的内容。

## 专用分支

**体细胞/基因组事件：**发布的 CHIP callset 与本地重新 calling 不同；记录 genome build、坐标、参考、过滤、染色体/PAR 边界、性别校准、事件到参与者的汇总和全分块覆盖。缺少原集群输入/日志时标记该段不能本地重现。`no call` 只有在确认样本通过覆盖和 QC 后才可编码为无事件；某块缺失不能静默当作全阴性。事件聚合脚本不能替代完整的变异识别与质量控制流程。

**衍生生物标志物：**先核对单位与公式成分，再讨论关联方向。年龄、血小板等既是评分成分又作调整变量时，估计的是条件关联；删除这些变量会改变 estimand，需另作批准的敏感性。公式成分或单位更正后，需追踪依赖结果及表图。

## 易错点及停止条件

| 观察 | 应做的事 | 不能做的事 |
|---|---|---|
| ID 重复或 join 扩行 | 查明重复层级并记录映射 | 任意去重以得到预期 N |
| 词典、代码、文稿不一致 | 给出各来源及影响，锁定任务版本 | 以日期最新的一项替全部定义 |
| 必需字段缺失 | 停止依赖模型，继续无关检查 | 用 intersect 静默删除必要协变量 |
| 插补或单位修正可能影响结果 | 列出依赖结果和估算重跑范围 | 手改已有核心统计数值 |
| 旧代码自动安装依赖 | 使用现有环境做预检，隔离执行入口 | 在“核查”时直接 source 整个脚本 |

验收：样本流和字典与派生结果可对照，输入保持原样，失败原因可定位；不要求为一次小变换制造通用框架。
