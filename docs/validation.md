# Validation scope

## 已有独立行为测试

2026-09-07，两项技能在隔离虚拟资料上接受独立 agent 执行测试；执行者未收到预期答案。主执行者核对实际输出和输入完整性。这里的独立不表示更换模型架构，也不代表外部研究验证。

| 用例 | 实际验收 |
|---|---|
| 结果来源核查 | 9 条虚拟论断拆为 16 个分句；接受正确舍入，识别效应标签、P/FDR、模型、尺度、集合方向和因果措辞问题；11 项检查通过。 |
| 图形修订 | 实际交付原生文本 SVG 与 PNG；重新解析实际估计/CI 坐标、模型与星号，检查最终 PNG；16 项检查通过。 |
| 触发范围 | 纯语法修改、新统计分析缺少输入和旧审阅指控三个场景。仅修改结果核查技能简介中的范围说明，随后由另一执行者复测；8 项检查通过。 |

完整原始评估报告留在私有审计档案，不在公开仓库伪装成可公开逐项复核的报告。本仓库提供无个人路径的 [虚拟核查输入](../examples/README.md) 和 [验收协议](../tests/skill_acceptance.md)，供使用者开展新的独立测试。

官方 skill-creator quick_validate.py 在当时已有环境中因缺少 PyYAML 未能启动；这项没有标记为通过。专用标准库检查只支持本仓库简单的单行 frontmatter，不是通用 YAML 解析器。

## 本公开包的机器检查

```bash
python scripts/validate_repository.py
python -m unittest discover -s tests -p "test_*.py"
```

第一条检查本地链接、简单技能 frontmatter、技能文件指纹、未定义研究参数及明显的本机路径/私有证据标记。第二条在临时目录测试单项复制、原样字节、拒绝覆盖和无效技能请求；不向真实个人技能目录安装。

发布时的实际结果保存在 [release_checks.json](../validation/release_checks.json)。机器扫描不能替代发布内容的人工审阅。

首次包装检查发现本机路径扫描把普通 HTTPS 链接误报，以及 Windows 测试子进程的输出编码不一致。已修正匹配边界、明确测试子进程编码，并增加输出 JSON 的实际读取检查；发布记录采用修正后的重新执行结果。

## 限制

没有重跑真实研究分析。图形行为测试只覆盖 SVG/PNG，不代表 Word、Excel、PowerPoint 或其他目标应用均已导入验证。安装器在 Windows/Python 环境执行过测试；采用标准库的实现仍需使用者在自己的系统上核查。文献和软件文档链接不代表已重新验证其中全部方法细节。
